## Lifecycle corrections and resource/performance limits

Independent real-browser testing caught a real transport-state defect and a
resource-retention observation before recording a technical pass. The parent
transport could show Pause after a terminal/reduced-motion Play refusal or Replay
reset. Separately, positive-size detached visible canvases remained reachable in
the development/test environment. A controlled follow-up removed retained test-driver
ElementHandles and the observed DOM retention disappeared. This supports a harness
retention explanation, but no heap retaining-path trace was taken; the earlier run
does not establish a product memory leak. Failed r1/r2 logs are retained. The P005 host now reconciles the parent's committed pause/replay request
with its actual clock state. The renderer's stable ref callback zeros a visible
canvas backing store when the node detaches, including render errors; its existing
cleanup zeros staging separately. Neither shared host code nor P006 was changed.

`independent-lifecycle-resources-r3.log` passed actual Play/Pause, paused resize and
font changes, keyboard seek, terminal Continue refusal, advancement from 967 to 968,
normal Replay, reduced-motion Play/Replay locking and no automatic resume after
motion preference returns to normal. Button action, aria-label and aria-pressed
now match the actual clock. Four Next/Previous cycles retained one staging and one
visible positive-size buffer when mounted; final unmount had zero positive-size
buffers, zero native figures/text, zero AudioContexts and zero audio starts.
Zero-sized DOM nodes remained reachable in that development/test run; this is
backing-store release evidence, not a claim that every DOM reference has been
reclaimed or that React itself caused their retention. A further r4 run used only
Locator waits, without retained ElementHandles. Across four cycles, mounted buffers
remained exactly two; after every unmount and final GC, the instrumented canvas
WeakRefs were empty, positive buffers were zero and visible-copy counts stopped
advancing. The explicit detach cleanup remains a useful deterministic backing-
store release; the initial retained-node observation is not labelled a React leak.
Terminal motion was exercised after seek; this was not an uninterrupted 80.6-second
visual run.

Three alternating complete 968-frame trials measured the original v2 adapter and
the native-title adapter including the visible canvas copy. Mean per-trial p95 was
15.733ms original and 15.300ms native; native/original total time ratio was 0.9723.
Allocations were 3384 vs 2416 per full sweep, a reduction of 968 wrapper surfaces.
A separate 2.5s real native-host observation captured 30 samples, frame 2→31, largest
step 1, visible-frame interval p50=82.2ms/p95=103.9ms, no context loss or audio.
A fresh navigation after the final host/ref corrections repeated the host-only
sample: 30 samples, frame 2→31, largest step 1, p50 interval 83.1ms/p95 126.5ms,
matching host/canvas frame identities, one 800×600 figure, correct paused control
and zero audio/context loss (`independent-host-performance-final.log`).
The cold original route compilation affected its first load measurement and is
not an improvement claim. These are same-Mac Chromium development measurements
under concurrent task activity, not production/mobile/long-duration latency or
listening evidence. See `independent-performance.log` for complete raw results.
