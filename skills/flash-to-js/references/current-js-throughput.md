## Lesson batches and separate delivery gates

For a calibrated path, the default delivery unit is one lesson or a named
compatible subset, not a new project for every page. A lesson can contain
multiple behavior families: keep their distinct assertions and isolate unknown
behavior. The first small calibration batch is not a permanent production cap.

State the requested gate before work. Use existing records and counters; do not
create a second ledger or collapse these stages into one `complete` boolean:

| Stage | Evidence needed to count it |
| --- | --- |
| Source-bound candidate | Exact placement/SWF identity, source hash, compiler/runtime provenance and reproducible module/data/media closure |
| Registry membership | Actual writer success and exact before/after active-ID intersection; name it membership, not complete Current-JS |
| My Lesson integration / Current-JS | Reviewed module/assets, exact source-ordered descriptor and admitted My Lesson presentation for that placement; registry rows alone are insufficient |
| Real playback and behavior | Current renderer actually draws, source-expected natural progression or intentional hold, and applicable page actions/Replay/navigation in required languages and configurations |
| Technical closure | All checks of the explicitly requested technical contract and its real closure receipt |
| Human/Owner and downstream acceptance | Their separate existing original-runtime, listening, review, strict-completion and publication authorities |

For a conversion-and-playback request, stop only when the requested pages have
the integration and relevant playback evidence, not at membership or first
paint. Stages may advance separately: a playback failure does not erase a valid
registry transaction, and a successful transaction does not hide that failure.
Do not wait for unrelated downstream gates before continuing authorized work.

Use this short execution loop:

1. Read the actual inventory once for the unit. Separate existing registered
   IDs, already generated candidates and truly missing implementations. Work
   on the missing stage; do not regenerate or re-audit unchanged source by habit.
2. Inspect the current writer/producer/loader contracts. Reuse the maintained
   packaging, registry and descriptor entry points. If a repeated format gap
   needs an adapter, implement it once with explicit page/lesson inputs; avoid
   copied per-page installers. Temporary scripts and old receipts locate an
   approach, not a maintained command or permission to run it.
3. Exercise the shortest real local My Lesson path on a representative candidate
   early, before a costly formal freeze/build/matrix. Diagnose loading, first
   paint, page selection and the relevant source action. This exploratory run
   earns no formal acceptance and never substitutes for required final checks.
4. Fix a common error in the compiler, runtime, host, loader or shared validator.
   Identify its consumers, retain a reproducer and relevant regression, then
   regenerate/recheck affected candidates. Preserve source/replay identity
   checks when resetting a VM or changing versions. A page-only exception needs
   source evidence that the shared implementation cannot express it safely.
5. Freeze the stable lesson/batch, keep each page's source/producer checks and
   use one writer. Share compatible build, dispatch, host/index and input reads
   only where the actual transaction supports it; keep required fresh execution
   and commit boundaries. Check partial failure/resume behavior before using
   a multi-page consumer. Never let an unchanged cached verdict authorize a write.
6. Read back membership and descriptors, then perform required real playback
   checks. Keep page/locale outcomes distinct. Reuse unchanged evidence by claim
   and dependency, not by blanket renewal or full-catalog reruns. Commit only
   the exact ready subset if the writer supports it, retain failed IDs and
   resume from that subset's receipt. Do not call a partial lesson complete.

### Real playback result rules

- Bind raw observations to the exact current placement, source/module/runtime,
  actual build or inspected dev candidate, runner, language, viewport and run
  times. Reuse existing manifests for these facts; filesystem mtime alone cannot
  establish candidate identity or completion time.
- Observe renderer completion and source-expected visible output in the actual
  My Lesson route. A parent `data-flash-frame`, `frame=1`, HTTP 200, a canvas
  element, exit 0 or `LESSON_DONE` is not a rendered-animation assertion. Pair
  renderer state with a meaningful screenshot/output observation; for animated
  pages also observe natural change, and for static/held states verify the
  source-backed expected content instead of demanding arbitrary motion.
- Wait for the current page's renderer, not the previous page or a parent clock.
  `blocked`, `error`, `failed`, `loading` at timeout, wrong-page and missing
  required resources cannot pass real playback. A lightweight frame-presence
  check may be reported under that exact name if requested, with no playback
  credit. Keep English source fallback separate from Spanish content acceptance.
- Exercise applicable page actions and Replay/state outcomes. Shared control
  tests may be reused for unchanged runtime contracts; they do not cover every
  page's content or state transitions. A first-page or one-viewport sample does
  not verify the remaining pages or a whole narrow-screen lesson.
- A service outage is an environment failure, not a page pass or an unproved
  product defect. A runner claiming playback success must return nonzero or an
  explicit failed/partial outcome on a required failure. Keep successful
  registration separately; never turn `SERVER_DOWN` into a successful lesson.
  Resume the failed stage after a verified recovery, without restarting already
  applicable passed work. Repeated unchanged failures require diagnosis before
  another retry; queue completion is determined by exact page/locale outcomes,
  not merely a process exit or the presence of a summary file.

Keep the existing checkpoint short: exact lesson/IDs and target gate, baseline
and net increment at each relevant stage, existing candidate reuse, wall time,
common fix, failing IDs/cause, evidence pointers and the next delivery action.
Update it after the unit, then immediately continue the authorized queue.
Infrastructure and skill edits receive zero page credit. A measured helper
improvement remains provisional until the next real batch shows how it affects
delivery at the same gate; record that follow-through rather than starting
another optimization study.

## Three independent checks

- Page proof: exact source, frozen producer output, implementation, historical
  observations and source-family semantics. Keep it unchanged for an unrelated
  registration. A hash difference in relevant evidence still fails closed.
- Shared host version: common runtime and integration inputs. A real shared
  behavior change requires scoped regression and a new host version. It does
  not require rewriting every page's historical receipt or acceptance date.
- Registration transaction: exact own calibration/entry/artifact identity plus
  complete canonical generation of both local-only dispatch files. Never ignore
  dispatch text or its production guard. A different page's addition changes
  the transaction, not the old page proof.

## Early registration and stable browser checks

Run `node scripts/g678-workflow.mjs preflight <calibration-fragment.json>` as soon
as the freeze and module/timeline/runtime artifacts exist. This calls the
production writer's validators and both dispatch generators in memory, without
writing the registry. V2 preparation additionally rejects supplied registration
pins that differ from what that writer would bind. A preflight pass does not
register a page or prove its behavior.

P017/P018 use `apps/web/components/source-lesson-host-bridge-v1.tsx` for bounded
main-audio loading, pause/playback reporting, host control connection, native
companion discovery and glossary-close handling. Their source clocks, audio
owners, frame domains and glossary instance gates remain page-owned. Reuse this
bridge only where those host semantics have been demonstrated on real pages.

Start the local server from the actual worktree, compile the selected routes,
then stop code edits and freeze a browser plan. The plan contains explicit
`animationIds` and `extraFiles` for the browser flow/driver and any additional
inputs used by that flow, and binds the server PID, worktree root and loopback
origin. Use a fresh browser session and unique output paths:

```
node scripts/g678-browser-candidate.mjs freeze <plan.json> work/g678-workflow/browser-candidates/<unique>.json
node scripts/g678-browser-candidate.mjs run <candidate.json> output/<unique>/stable-run.json -- <command> <args>
```

The freeze binds the active index, host, all retained page proofs and inputs,
real source closure, registry, complete dispatch and extra flow files. The run
checks bytes before and after, and watches input metadata during execution.
Any write, replacement or edit followed by a revert fails the run and retains
its receipt. Commands use argv without a shell. A successful stable command
still needs real browser assertions and their saved artifacts. After changing
code, review the host/page boundary and create a fresh candidate and receipt;
never relabel an older browser result current.

When assessing earlier evidence, use the
[claim-specific applicability rules](fidelity-validation.md#evidence-applicability-after-a-change).
Record reusable claims separately from fresh browser assertions; retain failed
attempts and their input-drift or assertion-failure reasons. Font enlargement,
header/canvas overlap, clipping and keyboard focus belong in the actual layout
matrix, not in a conclusion inferred from playback or horizontal overflow.

The current development-check entry point is
`HELP_MATH_G678_SOURCE_ROOT=<real AWS directory> node scripts/g678-workflow.mjs check`.
It uses the split-aware successor while retaining the old checker byte-for-byte:
the historical 379-page predecessor also pins that old checker. Do not edit that

## Source-family execution

`work/g678-workflow/CURRENT.json` joins the complete 2,282-placement manifest,
the structural inventory by exact source SHA and the real current registry.
Structural features route investigation; they do not authorize generation or
prove interaction semantics. Unknown behavior stays unknown. P012's audited
movement/coach state machine remains a separate advanced-manual exception.

For a new or materially changed source-behavior family, choose a representative
and finish source semantics, the real artifact roundtrip, My Lesson,
Replay/lifecycle, EN/ES and responsive checks before expanding that behavior.
Its first repeat calibration batch is at most five compatible pages. Never
label a family calibrated because its first page renders. For an unchanged,
already calibrated path, use the lesson/batch loop above; do not restart this
calibration or impose the initial five-page cap on routine production.

At 45 minutes without a newly integrated page or a resolved named blocker,
inspect the actual bottleneck and change the bounded implementation step.
After two producer/reader failures, fix the shared contract before another
page attempt. These are replanning triggers, not permission questions and not
permission to skip source work. Check whether a resolved blocker actually
shortened this lesson's delivery path; creating a script, receipt or benchmark
does not reset the delivery problem. Choose the smallest shared repair, verify
it and return to the current batch. Do not keep writing page-specific
infrastructure or receipts to fill successive turns.

## Measure work, not activity

Start an explicit unit before work:

```
node scripts/g678-workflow.mjs start <unique-unit> factory
node scripts/g678-workflow.mjs start <unique-unit> advanced-manual
node scripts/g678-workflow.mjs start <unique-unit> infrastructure
```

Finish once with `integrated`, `blocked`, or `infrastructure`. Integrated units
require a real EN/ES host receipt for new registry members:

```
node scripts/g678-workflow.mjs finish <unit> integrated <host-receipt.json>
node scripts/g678-workflow.mjs finish <unit> blocked unused rework
node scripts/g678-workflow.mjs report
```

The clock is observed wall time for that unit, not CPU time or an inferred bill.
Flag a rework unit when repairing a failed attempt. Infrastructure contributes
zero new pages. Historical per-page timing remains null unless an actual timer
exists; never estimate it from token usage. Report factory/manual yield and
rework separately. Do not substitute test counts or agent activity for pages.

Required regression: an unrelated registration with real regenerated dispatch
must leave old proof bytes untouched and admitted; changed own registration,
source, renderer, evidence, shared host, missing producer input, symlink, or
production guard must be rejected. Verify the actual product artifacts early,
then run one final build for the stable integration change.

## Measured efficiency changes

When a measured bottleneck justifies changing a shared reader, cache or batch,
use [g678-engineering-efficiency.md](g678-engineering-efficiency.md). It covers
actual caller profiling, comparable repaired baselines, fixed working-copy
inputs, single-request versus bounded-batch reuse, and complete proof/host
transitions. This is conditional improvement work, not a new phase for each page.

Inspect the current helper and receipts before proposing another cache. The
existing async admission scope and a scope spanning a complete formal operation
are different lifetimes. Measure the latter before adopting it. A five-page
read-only batch can share verified digest observations; five independent HTTP
requests cannot reuse that batch's cache. Keep code/descriptor measurements
separate from installed My Lesson and full closed-page throughput.

write claim to the actual build directory, service and run; retained old packs
are not evidence of new writes.

cost, yield and rework for comparable complexity and the same named product
gate before claiming an efficiency gain.
